# ADR-0005: 新規リポジトリ向け初期セットアップを独立CLIで提供する

## 背景

このリポジトリの開発ワークフローを別プロジェクトで使う場合、現在はテンプレートをcloneして手動で初期環境を整える必要がある。利用者向けの初期化入口がなく、生成物の不足や既存プロジェクトへの誤った途中導入を防ぎにくい。

## 決定と理由

新規Gitリポジトリだけを対象に、`create-project-work-flow`の独立CLIをローカルtarballで提供する。CLIはNode.jsで動作し、導入先アプリの言語には依存しない。生成物は一時領域で検証してから展開し、`.workflow/setup-manifest.json`に所有ファイルとハッシュを記録する。再実行と更新はこのマニフェストを基準にし、利用者の変更を検出した場合は停止する。

テンプレートをcloneする方式は現在の手順を再利用できるが、手動作業と対象判定が残るため採用しない。導入先からフレームワークを依存パッケージとして参照する方式は、検証スクリプト、テンプレート、設定を導入先の完了契約へ固定する責務を表現しにくいため採用しない。所有ファイルをCLIへ固定記述する方式は、更新時の版差分と利用者変更の検出を別の正本へ分散させるため採用しない。

独立CLIはパッケージの配布とNode.js実行を必要とする。個人用のローカルtarballから開始し、npm公開や自動更新は含めない。新規リポジトリを厳密に判定することで途中導入の自動マージ・自動上書きを避ける代わりに、既存コードへの導入は利用者が手動で設計する必要がある。

## 影響

- CLI、テンプレート、検証スクリプト、所有マニフェストの形式を同じ変更で保守する必要がある。
- npmまたはpnpmとNode.jsが初期化環境に必要になる。
- `--install`を使わない場合は依存導入を利用者が後から行う。
- `projectChecks`、外部接続、Gitコミットは利用者の責務として残る。
- パッケージ実行を伴うため、固定版tarballと出所を明示し、更新を利用者の明示操作に限定する。
