# アダプター認証宣言の照合

## 課題

作業マニフェストの`workflow.certified`は自己申告であり、参照するアダプターの
認証状態や固定コミットと照合されていない。

## 解決策

`certified: true`のマニフェストについて、アダプターIDの存在、アダプターの
`certified`状態、外部ワークフローの固定コミット一致を契約検証で強制する。
`certified: false`の候補ワークフローは従来どおり利用できる。

## ユーザーストーリー

1. レビュアーとして、未認証フローが認証済みを名乗れないように、宣言をアダプター記録と照合したい。

## 実装判断

- 純粋関数でマニフェストとアダプター一覧を照合する。
- 検証器は`adapters/*.json`を一度読み、各作業マニフェストへ適用する。
- ID不存在、候補状態、固定コミット不一致をそれぞれ具体的に報告する。

## テスト方針

- 利用者と合意した公開seamは、作業マニフェストとアダプター記録を照合する純粋関数と、
  リポジトリー全体の契約検証とする。内部呼び出しや実装詳細は検証しない。
- テストを先に追加し、機能不足を理由に失敗することを確認する。未認証宣言、
  認証済み宣言、ID不存在、候補状態、コミット不一致を既知の期待値で検証する。
- 純粋関数の単体テストと一時リポジトリーを使う統合テストを、既存の
  `scripts/workflow/contract.test.ts`に追加する。
- 最後に`npm run verify`を実行する。

## 対象外

- アダプターの認証テスト自体を自動実行する機能
- 外部SKILLの出力品質評価

## 補足

この入力はMatt Pocock版とsuperpowersの比較実験で共通利用する。
