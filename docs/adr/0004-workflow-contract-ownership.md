# ADR-0004: 開発手順から契約を分離し、人間とCLIで承認の責務を分担する

## 背景

開発SKILLは入れ替わるため、特定の手順へ成果物や完了条件を結び付けると、交換のたびに
プロジェクトの規約も変わってしまう。独自SKILLを開発・保守して既存SKILLと競争することも目的ではない。
また、生成された設計判断を自動で採用すると、会話での合意と実際の文章のずれを見落とす。

## 決定と理由

開発手順は外部ワークフローへ委ね、長期成果物と完了条件の契約はプロジェクトが所有する。
外部フローとの接続は形式・パス・状態の変換に限定し、情報不足を意味的な創作で埋めない。
外部SKILLの登録・認証は任意とする。必須にすると、その接続定義が交換の前提になり、
特定SKILLから独立した契約という目的を損なうためである。

設計判断の意味と採用の可否は人間が確認し、CLIは記録と対象の一致を検査する。
ADR本文を毎回人間が承認する方式を採用し、承認前はその判断に依存する本実装へ進めない。
指示とレビューだけに任せる方式に比べ手続きは増えるが、未承認や承認後の本文変更を
再現可能に検出できる。本文の承認記録は一時的な作業マニフェストではなくADRに残し、
作業終了後も何を承認したかを検査できるようにする。

この分担により、外部SKILLを改造せず交換でき、機械的な整合性検査を意味的な承認の代わりにしない。

## 影響

プロジェクトは契約・検証器・接続時の変換を保守する必要がある。
人間の本文確認が必要になり、誤字や整形だけでも本文が変われば再承認を求める負担を引き受ける。
ハッシュは本文との一致を確かめるもので、実際の読了や承認者の真正性を証明しない。
CLIは直接のファイル編集を物理的に禁止せず、指示・人間確認・独立レビューを併用する。
高リスク変更の最終コミット承認は、ADR本文の承認とは別に維持する。
