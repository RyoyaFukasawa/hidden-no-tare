# ADR-0002: 必須の完了契約と任意のワークフロー接続を分離する

## 背景

既存SKILLと競合する独自開発・保守は目的ではない。開発手順を交換するための
登録や認証そのものが必須になると、テンプレートが特定のSKILL構成へ依存する。
またコミットSHAの比較だけでは承認後の未コミット変更を検出できない。

## 決定と理由

外部SKILLとエージェントは全体・フェーズ・個別単位で交換する。
プロジェクトは長期成果物、形式、受け入れ条件、証跡、分類、レビュー、保存契約を所有し、
決定論的なCLIで検証する。意味的な判断は外部フロー、接続は薄いアダプターが担う。
変換できない情報は創作せず差し戻す。

変更マニフェスト・リスク分類・高リスク変更の人間承認は必須のまま維持する。
外部ワークフローの登録、固定バージョン記録、認証、比較実験は任意とする。
任意機能の削除・交換によって通常のverifyや文書契約が壊れてはならない。
利用する外部SKILLの出所・ライセンス・固定版・権限・危険命令の確認は継続する。
認証は指定版との境界適合性であり品質・安全性の保証ではない。

検証・独立レビュー・文書整理後にコミットし、高リスク変更はそのコミットを人間が承認する。
完了時にはHEADの一致に加え、通常のGit ignore対象と検証済み未追跡一時マニフェスト以外の
未コミット変更を拒否する。並行作業は別worktreeを使う。承認後の追加変更には再承認を要求する。

新規リポジトリへの導入を主対象にする。既存向け診断は限定した比較であり安全な移行を保証しない。
既存ファイルは承認なく上書きしない。外部ツールを許容し、必要版・導入方法・不足時の案内を提供する。

## 影響

ワークフロー情報なしで開発できる一方、任意の認証を使う利用者は別入口で確認する。
設定とマニフェストの型不正・欠落を実行時に拒否するため、従来黙認した不正データは修正が必要。
一時マニフェストは長期保存せず、承認後の追跡文書の更新も再承認の対象とする。
アーカイブ内の仕様・計画分割は引き続きSKILLに任せる。
