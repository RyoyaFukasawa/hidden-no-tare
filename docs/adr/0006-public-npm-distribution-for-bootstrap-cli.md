# ADR-0006: 初期セットアップCLIを公開npmパッケージで配布する

## 背景

ADR-0005では、初期セットアップCLIを個人用のローカルtarballとして提供した。利用者は毎回tarballの生成場所を確認し、`npm exec --package <tarball>`へパスを渡す必要がある。初期セットアップを自分の別プロジェクトで繰り返し使うには、この配布手順が過剰である。

## 決定案

`create-project-work-flow`を公開npmパッケージとして配布する。固定版を`npm create project-work-flow@<version>`または`npm exec --package create-project-work-flow@<version> -- project-work-flow update`で実行する。CLIは実行中のnpmパッケージに同梱されたテンプレートを使い、外部tarballの展開、`--from`引数、ローカルpack専用スクリプトを持たない。

初期化と更新は、実行したパッケージの`package.json`に記録された版をマニフェストへ保存する。更新は利用者が明示したnpmパッケージ版のCLIを実行して行い、既存の所有ハッシュ、利用者変更の停止、衝突停止、原子的な適用とロールバックはADR-0005の契約を維持する。公開npmパッケージを利用するため、実行時は固定版を指定し、Gitコミットは作成しない。

## 選択肢

- **公開npmパッケージ（採用案）**: コマンドが短く、版をnpmの仕組みで固定できる。パッケージ内容は公開される。
- ローカルtarball: 公開を避けられるが、tarballの生成・パス指定・保管が必要で、日常利用の負担が大きい。
- npmの非公開パッケージ: 内容を限定できるが、個人アカウントでの利用には有料プランと認証設定が必要になる。

## 影響

- npmレジストリへの公開と、公開物の内容確認・バージョン更新が必要になる。
- `npm create`から実行できるよう、パッケージ名と実行バイナリの契約を維持する。
- ローカルtarball生成、tarball展開、`--from`の分岐とテストを削除できる。
- 更新はネットワークと公開パッケージへの依存を持つため、固定版指定とnpmの整合性検証を利用者の運用に含める。

## 未決事項

- 公開パッケージ名が利用可能かを公開前に確認する。
- npm公開前に`npm pack --dry-run`相当の内容確認を検証CLIへ含めるかを決める。
