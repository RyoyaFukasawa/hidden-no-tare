# 01: 検証結果を簡潔に表示し、詳細ログを上限付きで保持する

## 実現する振る舞い

[変更仕様](../../../../work/token-efficiency/spec.md)のQ9・Q11・Q13に従い、検証内容を減らさず、通常表示を短くする。
成功時は要約、失敗時は診断の抜粋と詳細ログの場所を表示する。
必要な場合だけ詳細を読み、文脈へ流れ込む出力量を減らせるようにする。

## 依存チケット

なし（すぐに着手可能）。外部接続管理の実装を前提にしない。

## 受け入れ条件

- [x] 通常検証とfinalizeの検証出力が、成功時は要約、失敗時は診断とログ参照になる。
- [x] 検証の実行内容、失敗・未実行の判定、検証中の変更検出を維持し、成功のキャッシュで検証を省略しない。
- [x] 検証コマンドの詳細出力をGit管理外に保存する。会話履歴や思考過程は保存対象にしない。
- [x] ログの件数・容量に上限を設け、古いログから整理する。上限値と保持方法を利用案内に記載する。
- [x] 単独の過大出力は先頭と末尾を残して省略を明示し、その省略だけでは元の検証終了結果を変えない。
- [x] ログ保存障害は意図した省略と区別し、診断付きで失敗させる。
- [x] ログの保存・整理で検証対象、接続用ファイル、管理対象外のデータを変更しない。ログは移管対象の成果物と分離する。
- [x] 一時GitリポジトリのCLIで、成功、失敗、未実行、保存障害、上限整理、過大出力、finalizeの失敗時保持・成功時削除を確認する。
- [x] 同じ検証入力で変更前後の表示量を測定し、検証内容を減らさず出力量が減った証跡を残す。実際のtoken消費や課金の削減率とは区別する。
- [x] 現行仕様と利用案内を同期し、独立レビューと完了文書の整理を行う。整理後の通常検証を成功させる。

## 検証結果

CLIテストで通常表示、finalize、過大出力の終了コード7の維持、保存障害、symlink拒否、
10件・合計5MiBの整理、完了境界の失敗のログ保存を確認した。関連78テストと型チェックが成功。
各追加ケースの不成功を確認してから実装し、成功へ進めた。

同じ一時Gitリポジトリ・同じ検証入力で、比較元c148215のverifyと変更後を実行した。
表示は15,414バイトから928バイトへ減少（約94%減、両方終了コード0）。
測定は[再現用スクリプト](../measure-output.ts)をリポジトリルートから実行した。
この値はUTF-8の表示量であり、実際のモデルのtoken消費や課金の削減率ではない。
規約担当compact_logs_standardsと仕様担当compact_logs_specが比較元c148215から独立レビューした。
両担当が指摘した「Gitの所有確認失敗時にログ整理を省略する」P2を修正し、
CLIの回帰テストを追加した。両担当が修正を確認し、残る指摘はない。
Git追跡へ変更されたログと、管理名に似せた利用者ファイルの保持も追加確認した。
アーカイブ後の通常検証が成功し、全176テスト・型チェック・完了契約・ADR・Markdown・リンク検証を通過した。
測定用スクリプトも移動後に再実行し、15,414バイトから928バイトという結果を再確認した。
完了契約に関わる変更として扱い、最終SHAへの人間承認は一時マニフェストで管理する。
