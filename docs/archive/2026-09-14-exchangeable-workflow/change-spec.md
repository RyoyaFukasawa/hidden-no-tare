# 交換可能な開発ワークフロー契約

## 課題

特定の開発SKILLへ文書形式と完了手順を密結合すると、より良いSKILLへの移行時に
プロジェクトの履歴と運用まで変更される。一方、外部SKILLに対抗する独自SKILLの
開発と継続保守は目的に合わない。

## 解決策

外部ワークフローを交換可能な実装として扱い、長期成果物と完了判定を
プロジェクト所有の契約として分離する。状態と検証をCLIへ集約し、外部SKILLとの
差は意味的判断を行わない薄いアダプターで接続する。

## ユーザーストーリー

1. 開発者として、優れた新しいSKILLへ安全に移行するために、開発フローを交換したい。
2. レビュアーとして、未検証や未確認の変更を防ぐために、同じ完了契約で判定したい。
3. 保守者として、既存プロジェクトを壊さず導入するために、衝突を事前診断したい。

## 実装判断

- 状態、リスク、成果物、検証、レビュー、例外を純粋なTypeScript契約として定義する。
- 設定は`workflow.config.json`を正本とする。
- `verify:contract`と`verify:project`を分離し、`verify`から統合する。
- 外部ワークフローはGitコミットで固定したアダプターマニフェストとして宣言する。
- 新規変更は`researching`から開始し、未分類のまま本実装へ進めない。
- 既存プロジェクトへの導入は読み取り専用診断から始め、自動上書きしない。

## テスト方針

- 契約判定はファイルシステムから分離して単体テストする。
- 正常完了、未分類、失敗検証、高リスク承認、期限切れ例外を検証する。
- 敵対的な偽SKILLで危険な命令と秘密情報アクセスの検出を検証する。
- 既存プロジェクト診断が既存ファイルを変更しないことを検証する。
- `npm run verify`で型、テスト、文書、リンク、ADR、完了チケットを統合検証する。

## 対象外

- 外部SKILLの判断品質の保証
- 外部SKILLの完全なセキュリティ保証
- Matt Pocock版とsuperpowersによる同一課題の実地比較
- テンプレートCLIのパッケージ公開

## 補足

実地比較は交換可能性の最終的な実証として、別の変更チケットで行う。
