現行仕様が増えたのは、共通ルールの正本を集約し、Mattのライフサイクルを記載したため。
参照先も合計に含めると、共通文書全体の削減は小さい。入口の57.8%減を全体の削減率とは呼ばない。
実際に必要な節だけ読む運用と入口の短縮が主な狙いであり、規則や検証の省略ではない。

Matt固有文書は、変更前の`docs/agents/domain.md`と`issue-tracker.md`の合計と、
変更後に定義から生成する本文の合計を比較した。後者は接続した場合だけ読む。
再生成用JSON自体は833 bytesであり、生成本文との二重計上を避けて別記する。
この値にSKILL本体・未変更のテンプレート・アーカイブ・会話履歴は含めない。
`.codex/skills/`・採用済みADR本文・CONTEXT.mdは変更していない。

リポジトリルートから再測定できる（変更後は現在の作業ツリーを読む）。

```sh
node docs/archive/2026-09-15-matt-connection-isolation/measure-documents.ts
```

規則の保存先は次のように整理し、独立レビューで移管漏れを確認した。

- 仕様・チケットのローカル管理、ready-for-agent、テンプレート、作業場所、アーカイブ：現行仕様の「文書の管理」。
- ADRの選別・本文承認・依存・置き換え：現行仕様の「ADRの選別と本文承認」。
- 分類、独立レビュー、最終SHA、Git状態：現行仕様の「必要成果物」「リスクとレビュー」。
- 検証と診断ログ：現行仕様の「検証」「検証表示と診断ログ」。
- Mattの設定と参照：任意定義が生成する互換文書。共通ルールの新しい正本にはしない。
