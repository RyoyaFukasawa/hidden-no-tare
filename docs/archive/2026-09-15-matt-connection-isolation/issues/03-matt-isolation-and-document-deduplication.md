外部SKILL本体を変更せず、02の仕組みでMatt接続の準備・利用・撤去を確認する。

## 受け入れ条件

- [x] 共通規則の正本をプロジェクト側に残し、Mattが必要とする接続設定・参照を任意接続の再生成用定義へ分離する。
- [x] 共通規約・現行仕様・固有文書の重複を整理し、必要な規則や参照、ローカルの仕様・チケット管理方針を失わない。
- [x] Matt固有の固定パス文書は接続時に用意され、撤去時に安全に片付く。既存の追跡文書の移行と、通常の接続時の上書き拒否を区別する。
- [x] 実際のMatt接続定義で準備・撤去を確認し、固有文書がなくても通常の共通検証・完了判定を実行できる。
- [x] 常時読む案内から全外部固有文書の読込を要求せず、必要な接続情報へ選択的に到達できるようにする。
- [x] 共通側へ移管した仕様・チケット・判断などの長期成果物は、接続を撤去しても保持される。
- [x] 外部SKILL本体を改造せず、登録・認証・同梱例を通常検証の必須条件にしない。接続成功を認証済みの宣言と混同しない。
- [x] 一時GitリポジトリのCLIで、Matt接続の準備・撤去、固定パス競合、成果物の保持、接続なしの通常検証を確認する。
- [x] 常時参照する共通文書量と任意の外部固有文書量を分けて変更前後を測定し、常時参照量の削減を確認する。別の必読文書へ移しただけの削減とは区別する。

- [x] 現行仕様・エージェント向け案内・利用案内を同期し、完了文書整理後の通常検証を成功させる。
