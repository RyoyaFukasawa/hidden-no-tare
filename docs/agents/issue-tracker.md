# 仕様・チケットの管理先

管理先はリポジトリ内のローカルMarkdownとする。GitHub Issueへの公開は行わない。
これはto-spec実行時に利用者が選択した運用である。

## 仕様の公開

既存の変更仕様がある場合は同じ文書を更新し、重複した仕様を作らない。
仕様の形式はプロジェクトの変更仕様テンプレートを使う。
実装担当に渡せる仕様は、YAMLメタデータに`status: ready-for-agent`を付ける。
ローカル運用ではこれをto-specのready-for-agentトリアージラベルに相当する表現とする。
この状態は実装完了を意味しない。

## チケットと保存先

チケットはプロジェクトのチケットテンプレートと状態値に従う。
作業中の保存場所は固定せず、採用するSKILLに任せる。
完了文書の保存先、アーカイブ、現行仕様の更新はAGENTS.mdに従う。
軽微変更のチケット省略は現行仕様の分類・独立レビュー・完了条件に従う。
