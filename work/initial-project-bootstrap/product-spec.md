# 新規プロジェクト初期セットアップ

## 目的・範囲

新しいGitリポジトリを作成した開発者が、交換可能な開発ワークフローを別プロジェクトで使い始めるための初期セットアップを提供する。
対象は初回開発前のリポジトリに限り、既存プロジェクトへの途中導入は扱わない。

## 現行の仕様

### 新規リポジトリの判定

| 条件・操作 | 期待する結果 |
| --- | --- |
| GitのHEADがあり、ルートに`.gitignore`または`README.md`以外の利用者ファイルがない | 初期セットアップを開始できる |
| GitのHEADがない | 初回コミットの案内を表示して停止する |
| 許可されない既存ファイルがある | 既存プロジェクトへの途中導入は対象外と表示して停止する |

### 初期セットアップ

公開npmパッケージの`create-project-work-flow`を`npm create project-work-flow@<version>`で初期化コマンドとして実行する。プロジェクト名は現在のディレクトリ名を初期値とし、コマンドライン引数または対話入力で上書きできる。パッケージマネージャーはnpmまたはpnpmを自動検出し、判定できない場合は対話で選択する。

CLIは一時領域で生成物を検証した後、`AGENTS.md`、`workflow.config.json`、ワークフロー用テンプレート、検証スクリプト、Node.js実行設定、package scriptsと依存関係を展開する。`projectChecks`は空配列で開始する。

`--install`を指定した場合だけ選択したパッケージマネージャーで依存関係を導入する。CLIはGitコミットを作成しない。利用者が差分を確認してコミットする。
既存の`.gitignore`へ除外規則を追記する場合は差分を表示し、`--accept-existing`を指定したときだけ追記する。

### 再実行と更新

初期化済みマニフェストがあり、同じ版・同じ内容であれば再実行を成功扱いにする。差分がある場合は上書きせず停止する。

`workflow:update`は固定版のnpmパッケージを`npm exec --package create-project-work-flow@<version> -- project-work-flow update`で実行し、そのパッケージに同梱されたテンプレートからフレームワーク所有ファイルだけを更新する。所有ファイルに利用者の変更がある場合や、新しい所有パスが既存ファイルと衝突する場合は差分を表示して停止する。`--dry-run`では初期化・更新の変更予定と実行予定コマンドだけを表示する。

### 完了条件

初期化後に依存関係の導入を必要に応じて実行でき、生成されたプロジェクトで`npm run verify`または`pnpm run verify`と最初の`workflow:prepare`が成功する。
