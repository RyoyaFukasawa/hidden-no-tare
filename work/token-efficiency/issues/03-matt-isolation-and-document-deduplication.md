# 03: Matt固有文書を任意接続へ移し、共通文書の重複を減らす

## 実現する振る舞い

[変更仕様](../spec.md)の共通契約と外部接続の分離、および文書読込量の削減を実現する。
Mattが要求する接続情報を共通の規約から切り離し、必要な接続だけを参照できるようにする。
外部SKILL本体を変更せず、02の仕組みでMatt接続の準備・利用・撤去を確認する。

## 依存チケット

- [02: 外部接続を安全に準備・撤去し、未移管データを残した完了を拒否する](02-external-connection-lifecycle.md)

01への依存はない。文書量の測定は検証ログの簡潔化と独立して行える。

## 受け入れ条件

- [ ] 共通規則の正本をプロジェクト側に残し、Mattが必要とする接続設定・参照を任意接続の再生成用定義へ分離する。
- [ ] 共通規約・現行仕様・固有文書の重複を整理し、必要な規則や参照、ローカルの仕様・チケット管理方針を失わない。
- [ ] Matt固有の固定パス文書は接続時に用意され、撤去時に安全に片付く。既存の追跡文書の移行と、通常の接続時の上書き拒否を区別する。
- [ ] 実際のMatt接続定義で準備・撤去を確認し、固有文書がなくても通常の共通検証・完了判定を実行できる。
- [ ] 常時読む案内から全外部固有文書の読込を要求せず、必要な接続情報へ選択的に到達できるようにする。
- [ ] 共通側へ移管した仕様・チケット・判断などの長期成果物は、接続を撤去しても保持される。
- [ ] 外部SKILL本体を改造せず、登録・認証・同梱例を通常検証の必須条件にしない。接続成功を認証済みの宣言と混同しない。
- [ ] 一時GitリポジトリのCLIで、Matt接続の準備・撤去、固定パス競合、成果物の保持、接続なしの通常検証を確認する。
- [ ] 常時参照する共通文書量と任意の外部固有文書量を分けて変更前後を測定し、常時参照量の削減を確認する。別の必読文書へ移しただけの削減とは区別する。
- [ ] 文書量の測定値を実際のtoken消費の削減率と同一視しない。規則の移行漏れとSKILL本体の無変更を独立レビューで確認する。
- [ ] 現行仕様・エージェント向け案内・利用案内を同期し、完了文書整理後の通常検証を成功させる。

## 検証結果

未実装・未検証。02の完了契約を満たしてから着手する。
ready-for-agentは追加のトリアージが不要という意味であり、依存を無視して着手してよいという意味ではない。
規則や承認条件の緩和で文書量を減らさず、変更全体の最終承認は一時マニフェストで別途管理する。
