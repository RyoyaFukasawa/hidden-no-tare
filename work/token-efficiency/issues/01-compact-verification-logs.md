# 01: 検証結果を簡潔に表示し、詳細ログを上限付きで保持する

## 実現する振る舞い

[変更仕様](../spec.md)のQ9・Q11・Q13に従い、検証内容を減らさず、通常表示を短くする。
成功時は要約、失敗時は診断の抜粋と詳細ログの場所を表示する。
必要な場合だけ詳細を読み、文脈へ流れ込む出力量を減らせるようにする。

## 依存チケット

なし（すぐに着手可能）。外部接続管理の実装を前提にしない。

## 受け入れ条件

- [ ] 通常検証とfinalizeの検証出力が、成功時は要約、失敗時は診断とログ参照になる。
- [ ] 検証の実行内容、失敗・未実行の判定、検証中の変更検出を維持し、成功のキャッシュで検証を省略しない。
- [ ] 検証コマンドの詳細出力をGit管理外に保存する。会話履歴や思考過程は保存対象にしない。
- [ ] ログの件数・容量に上限を設け、古いログから整理する。上限値と保持方法を利用案内に記載する。
- [ ] 単独の過大出力は先頭と末尾を残して省略を明示し、その省略だけでは元の検証終了結果を変えない。
- [ ] ログ保存障害は意図した省略と区別し、診断付きで失敗させる。
- [ ] ログの保存・整理で検証対象、接続用ファイル、管理対象外のデータを変更しない。ログは移管対象の成果物と分離する。
- [ ] 一時GitリポジトリのCLIで、成功、失敗、未実行、保存障害、上限整理、過大出力、finalizeの失敗時保持・成功時削除を確認する。
- [ ] 同じ検証入力で変更前後の表示量を測定し、検証内容を減らさず出力量が減った証跡を残す。実際のtoken消費や課金の削減率とは区別する。
- [ ] 現行仕様と利用案内を同期し、独立レビューと完了文書の整理を行う。整理後の通常検証を成功させる。

## 検証結果

未実装・未検証。仕様のQ12に従い、CLIの終了コード・出力・ファイルの保持と削除を確認する。
チケット作成時の既存テスト成功を、このチケットの受け入れ条件の証拠にはしない。
完了契約に関わる変更として扱い、最終SHAへの人間承認は一時マニフェストで管理する。
