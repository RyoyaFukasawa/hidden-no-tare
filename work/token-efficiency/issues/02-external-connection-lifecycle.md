# 02: 外部接続を安全に準備・撤去し、未移管データを残した完了を拒否する

## 実現する振る舞い

[変更仕様](../spec.md)のQ1〜Q8・Q10に従い、外部接続ごとに専用領域を持ち、
固定パスの互換ファイルも含めて準備・撤去できるようにする。
保存すべきか不明なデータを勝手に消さず、未移管データを残した完了を止める。
任意の接続定義を扱う共通の仕組みとし、Matt固有の移行は03で行う。

## 依存チケット

なし（すぐに着手可能）。検証ログの簡潔化を前提にしない。

## 受け入れ条件

- [ ] Git管理する再生成用の接続定義から、接続別のGit管理外領域を明示CLIで準備できる。
- [ ] 固定パスの互換ファイルも接続側の所有対象として管理し、専用領域外の例外を撤去時に取り残さない。
- [ ] 複数の独立した接続を併用できる。既存ファイルや他接続との固定パス競合は拒否し、元の内容を保持する。
- [ ] 撤去は接続側が生成し、生成後に変更されていないと確認できる管理ファイルだけを対象にする。
- [ ] 未移管・変更済み・所有不明のデータが残っていれば、診断付きで撤去を拒否し、データを保持する。
- [ ] 完了時は同じworktree内の全接続を検査し、未移管データがあれば拒否する。別worktreeへ干渉しない。
- [ ] 作業データを共通側へ移管、または明示的に破棄した後は、他の条件を満たせば完了・撤去できる。意味的な自動移管・自動破棄はしない。
- [ ] 再生成できる未変更の接続ファイルは完了時にも残せる。調査・実装中の資料の存在だけで通常検証を一律に止めない。
- [ ] 接続が一つもなくても共通の検証・完了判定が動く。通常検証は接続用ファイルを生成・撤去しない。
- [ ] 不正な定義や所有記録を成功扱いせず、他接続、共通成果物、worktree外のデータを上書き・撤去しない。
- [ ] 分類、必要成果物、検証証跡、独立レビュー、ADR本文承認、最終SHA承認、Git状態、検証中の変更検出とfinalizeの記録保持を維持する。
- [ ] 一時Gitリポジトリの接続・撤去・verify・finalize CLIで、準備から撤去までの正常系と上記の拒否・保持を確認する。
- [ ] 現行仕様と利用案内に、領域・コマンド・所有記録の扱いを明文化する。物理的なサンドボックスと説明しない。
- [ ] SKILL本体のインストール・更新・改造を行わず、独立レビュー・完了文書整理後の通常検証を成功させる。

## 検証結果

未実装・未検証。仕様のQ12に従い、CLIの終了コード・出力・ファイルの保持と削除を確認する。
完了契約と撤去処理に関わるため軽微変更として扱わず、最終SHAへの人間承認は一時マニフェストで管理する。
