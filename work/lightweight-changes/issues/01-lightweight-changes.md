# 01: 軽微変更だけチケットなしで完了できるようにする

## 実現する振る舞い

[合意した変更仕様](../spec.md)に従い、誤字・コメント・整形の軽微変更では
マニフェストによる管理と検証・独立レビューを維持し、チケットとそのアーカイブを省略できる。
省略できる正常系と、不正な分類や未検証を拒否する条件を同時に提供する。
チケットの代わりとなる長期文書は増やさない。

## 依存チケット

なし（すぐに着手可能）。to-ticketsで1チケット構成と依存なしを利用者が承認済み。

## 受け入れ条件

- [ ] 意味を変えない誤字・コメント・整形を軽微変更として宣言し、空でない分類理由・検証結果・独立レビューを記録すれば、チケットとそのアーカイブなしで完了できる。
- [ ] 軽微変更でもマニフェストを必須とし、代替の長期文書や省略の都度の人間承認を追加しない。
- [ ] 通常扱い・軽微変更の宣言がない従来形式では、チケットを含む既存の成果物要件を維持する。
- [ ] 分類理由・検証・レビューの不足、失敗や未実行の検証、JSON型不正、変更特性・高リスクとの矛盾を拒否する。
- [ ] レビューで分類が否定された場合や判断が曖昧な場合は通常扱いへ戻し、チケットなしでは完了できない。
- [ ] 軽微変更でもレビュー対象とHEADの不一致、staged・unstaged・untracked変更を従来の例外条件を除き拒否する。
- [ ] 検証中に生成された未コミット変更や完了マニフェストの変更・削除を拒否する。
- [ ] finalizeは拒否時に対象マニフェストを自ら削除せず、成功時だけ削除する。
- [ ] 既存のverify／finalize CLIを実際の一時Gitリポジトリで実行し、上記の成功・拒否を終了コード・診断・記録の保持や削除で検証する。既存テストも維持する。
- [ ] 現行仕様・エージェント向け指示・利用案内をCLIと同時に更新し、分類理由と独立レビューの記録方法、通常扱いへ戻す手順を記載する。
- [ ] 利用案内にリファクタリング・不具合修正・高リスク変更が対象外であることと、意味の同一性を行数やファイル名だけで判定しないことを記載し、「必須」を「任意」に変える修正は通常扱いになる例を示す。
- [ ] 独立レビューと文書整理を行い、整理後のnpm run verifyが成功する。

## 検証結果

CLIの正常系・分類理由・分類確認・変更特性の矛盾について、失敗するテストを確認してから実装した。
一時Gitリポジトリを用いるrepository.test.tsは61テスト成功。型検証も成功した。
独立レビュー・文書整理はまだ完了していないため、受け入れ条件は未チェックのままとする。

今回の仕組みの変更自体は高リスクの通常扱いである。検証・独立レビュー・文書整理後の
コミットSHAへの人間承認は必須のまま維持し、利用者の了承により記録先を一時マニフェストへ分離する。
チケットのdoneは実装・検証・独立レビューの完了であり、変更全体の承認・finalize完了ではない。
人間承認前に変更マニフェストをcompleteにしない。
