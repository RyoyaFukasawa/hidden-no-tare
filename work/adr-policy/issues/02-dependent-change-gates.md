# 02: 未承認ADRに依存する実装・完了を止める

## 実現する振る舞い

[変更仕様](../spec.md)に従い、変更とADRの依存関係を検証し、未承認・本文不一致の
判断に依存する本実装への移行と完了をCLIで拒否する。
調査・試作の検証と、無関係な有効草案があるだけの別変更は止めない。

変更仕様のQ5・Q8・Q12を主に扱う。先行チケットが提供する草案・承認記録・本文一致の
検査を利用し、ADR単体の承認ルールを別の場所で重複して定義しない。

## 依存チケット

- [01: ADRを選別し、本文承認付きで管理できるようにする](../../../docs/archive/2026-09-15-adr-body-approval/issues/01-adr-approval-and-migration.md)

草案と有効な本文承認を区別する検査、および既存ADRの移行が完了してから着手する。

## 受け入れ条件

- [ ] 影響を受ける変更と判断の依存を明示的に検証でき、依存するADRの承認状態と本文の一致を確認できる。
- [ ] 未承認の判断に関する調査・試作は許可するが、その判断に依存する本実装への移行と完了は診断付きで拒否する。
- [ ] 有効な本文承認があり、他の既存条件も満たす変更は、本実装への移行と完了の検証を通る。
- [ ] 承認後に本文が変わった場合は、誤字・整形・リンクだけでも依存する本実装への移行と完了を拒否する。新しい本文の承認後は再び検証を通せる。
- [ ] 存在しない依存先や不正な依存入力を成功扱いせず、Accepted表記だけ、承認記録の欠落・不正、本文不一致で承認済みと扱わない。
- [ ] 形式の正しい未承認草案があるだけでは通常のverifyを一律に失敗させず、その草案に依存しない変更の検証を妨げない。
- [ ] 不正な承認済み記録や本文不一致は、正常な草案があるだけの状況と区別して拒否する。
- [ ] 既存の分類・リスク・必要成果物・検証証跡・独立レビュー・高リスクの最終SHA承認を維持する。
- [ ] 承認後のHEAD変更、完了時の未コミット変更、検証中の記録変更を成功扱いしない。既存の完了処理の失敗時保持・成功時削除を維持する。
- [ ] 実際の一時Gitリポジトリで既存のverify・ADR検証CLIを使い、調査可能・実装移行拒否・完了拒否・承認後成功・本文変更後失効・無関係な草案のケースを終了コードと診断で確認する。
- [ ] 現行仕様・エージェント向け指示・利用案内を同期し、CLIを通さない編集自体の物理的な禁止や、人間の読了の自動証明を保証しないことを説明する。
- [ ] 独立レビューと文書整理を行い、整理後のnpm run verifyが成功する。先行チケットのADR承認検査も回帰しない。

## 検証結果

01は最終SHAへの人間承認・finalize・main統合を完了してから本チケットへ着手した。
比較元は統合済みmainの`e704bf6`。既存のADR-0004本文は変更していない。

- `scripts/workflow/repository.test.ts`で調査中の草案許可、ready以降の拒否、成果物からの依存、
  不正依存入力、承認後成功、本文変更後失効、再承認、無関係な草案、finalizeの保持・削除を確認。
- 依存検査はADR単体の検証を再利用する。依存の意味的な申告漏れはレビューの責務として残す。
- TDDで依存未対応による失敗と、ADR成果物の検査漏れによる失敗をそれぞれ確認してから実装した。
- 独立レビュー・最終検証・文書整理は実施中。

この変更は完了契約に関わるため軽微変更として扱わない。
検証・独立レビュー・文書整理後の最終SHAへの人間承認は一時マニフェストで別途管理し、
承認前に変更全体をcompleteにしたりfinalizeしたりしない。
